# 指标上线前的复核清单

给评审会用的，逐条打勾；打不了勾就退回 draft。顺序按「最容易被忽略」排。

## 口径

- [ ] 分母写清楚了吗？（退款率的分母是「已支付订单」还是「全部订单」）
- [ ] 时间归属按哪一端？（下单时间 / 支付时间 / 发货时间，三者差一到两个月很正常）
- [ ] 时区是 Asia/Shanghai 还是 UTC？跨日边界怎么算？
- [ ] 状态过滤是否包含退款、取消、测试单、内部账号？
- [ ] 金额是含税/不含税、含运费/不含运费？

## 数据

- [ ] 来源表在 `sql/` 里有 DDL 声明？
- [ ] 公式里出现的每个表都在 `source_tables` 里？
- [ ] 粒度明确（订单级 / 明细级 / 用户日级）？重复计数怎么避免？
- [ ] 空值、负值、异常大值的处理规则写了？

## 工程

- [ ] `metric_code` 符合小写下划线规范、没和已有指标撞车？
- [ ] `version` 递增了吗？口径变更有没有留旧版本？
- [ ] CI 通过（`python scripts/validate_dictionary.py` 退出码 0）？
- [ ] 下游看板已经切到新口径、并通知了使用方？

## 交付

- [ ] 有没有一个可复现的 SQL 示例（放 `sql/`）？
- [ ] 报表里的注释指向 `metric_code` 而不是中文名？
- [ ] 三个月后接手的人，只看字典能不能重建这个数字？

> 最后一条是真正的验收标准。前十四条都是为了它。
